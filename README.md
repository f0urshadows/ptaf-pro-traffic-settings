# PTAF Traffic Settings Client

Chrome/Edge extension for working with PTAF `/api/ptaf/v4/config/traffic_settings/`.

## v0.3.0

- Authentication settings are moved into a collapsible block.
- Existing saved connection profile keeps the auth block collapsed by default.
- Traffic settings editor is more compact: every top-level key is rendered as a dense row with name, type and editable value.
- PATCH success is logged in the popup.
- The last successful PATCH time/date is persisted in `chrome.storage.local` and shown in the header.
- The extension stores a short UI event log for GET, PATCH, auth check, profile save and errors.

## Security model

The PTAF password is encrypted with Web Crypto AES-GCM. The encryption key is generated by the browser as a non-extractable `CryptoKey` and stored locally in IndexedDB. The password itself is stored in `chrome.storage.local` only as ciphertext.

This is a browser-native local encryption approach, but it is not the same as using an operating-system keychain. If Chrome profile data is deleted or migrated incorrectly, the key can be lost and the profile must be saved again.

## TLS note

Browser extensions cannot disable TLS verification like Python `requests(..., verify=False)`. If PTAF uses a self-signed certificate, trust that certificate in the OS/browser first.
